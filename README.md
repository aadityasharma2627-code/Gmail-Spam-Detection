# 📧 Gmail Spam Detection System

An AI-powered web app that connects to your Gmail account, scans your latest emails, and classifies each one as **Spam** or **Ham** with a confidence score. A local **Gemma 4** model (via Ollama) can then explain in plain language *why* an email looks suspicious, without sending the email text to any cloud AI service.

Instead of pasting email text by hand, the app reads emails straight from Gmail and shows the results on a clean dashboard.

## 🚀 Features

- 🔐 Secure Gmail login with Google OAuth 2.0
- 📥 Scan the latest 10, 25, 50 or 100 emails
- 🤖 Spam / Ham prediction with a confidence score (Subject + Body)
- ✨ **Explain with Gemma 4**: verdict, short reason and red flags for any email, running locally
- ✍ Manual prediction for any text you paste
- 🔍 Search scanned emails by subject
- 📊 Spam vs Ham statistics chart
- 🌙 Dark / Light theme

## 🧠 How It Works

```
Google OAuth login
      │
      ▼
Gmail API  →  fetch Subject + Body
      │
      ▼
Text preprocessing  →  TF-IDF  →  Logistic Regression
      │
      ▼
SPAM / HAM + confidence  →  dashboard
      │
      ▼  (on click)
Gemma 4 via Ollama  →  verdict, reason, red flags
```

**ML model:** TF-IDF (unigrams + bigrams, up to 50,000 features) with Logistic Regression, trained on about 298,000 labelled emails.

| Metric | Result |
|--------|--------|
| Accuracy | 97.6% |
| Spam precision / recall | 0.94 / 0.98 |
| Ham precision / recall | 0.99 / 0.98 |

**Gemma 4 explanation:** classifies an email as `spam`, `promotional` or `ham` and gives a one-line reason with up to three red flags. It is a small model running on your own machine, so treat it as a second opinion next to the ML model, not as the final answer.

## ⚙ Installation

### 1. Clone the repository
```bash
git clone https://github.com/aadityasharma2627-code/Gmail-Spam-Detection.git
cd Gmail-Spam-Detection
```

### 2. Create a virtual environment
Windows:
```bash
python -m venv venv
venv\Scripts\activate
```
Linux / macOS:
```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Install dependencies and NLTK data
```bash
pip install -r requirements.txt
python download_nltk.py
```
Make sure `requests` is listed in `requirements.txt` (the Gemma helper uses it).

### 4. Download the dataset
The dataset is not included because of its size. Download `email_dataset_classification.csv` from
[Kaggle](https://www.kaggle.com/datasets/nikhilchaudhary7108/spam-email-datasetenron-trec-and-others) and place it here:
```
dataset/email_dataset_classification.csv
```

### 5. Train the model
```bash
python train_model.py
```
Cleaning about 300,000 emails takes several minutes the first time (a cache file is saved for later runs). This creates `model/spam_model.pkl` and the vectorizer files.

### 6. Set up Gmail API access
This repository does not include Google credentials. Create your own:

1. Open [Google Cloud Console](https://console.cloud.google.com/) and create a project
2. **APIs & Services → Library**: enable **Gmail API**
3. **OAuth consent screen**: choose External and add your Gmail address under **Test users**
4. **Credentials → Create Credentials → OAuth client ID → Desktop app**
5. Download the JSON, rename it to `credentials.json` and place it in the project root

While the app is in *Testing* mode, only the Test users you added can sign in, and the login token expires after about 7 days (delete `token.json` and log in again).

### 7. (Optional) Set up Gemma 4 with Ollama
1. Install Ollama: https://ollama.com/download
2. Download the model:
   ```bash
   ollama pull gemma4:e2b
   ```
3. Keep Ollama running in the background
4. Start the app and wait for `Gemma warmup done` in the terminal. On a laptop without a GPU the first load can take 2 to 3 minutes, and each explanation takes roughly 25 to 40 seconds.

Quick check: `python gemma_test.py`

### 8. Run the app
```bash
python app.py
```
Open http://127.0.0.1:5000, click **Scan Gmail**, and sign in on the first run. Use **Explain with Gemma** on any email.

## 🧪 Testing without Gmail

Use the **Manual Prediction** box with any subject and body, or run `python gemma_test.py` to test the Gemma helper alone.

## 🔒 Security Notice

These files are never committed and must be created by each user:

- `credentials.json`
- `token.json`
- `.env`

Never upload them to GitHub. All email text is processed on your own machine; Gemma runs locally through Ollama.
